Помогает решить, что поесть:

- **Веб-приложение (на телефоне на кухне):** книга из 80+ рецептов (плита и аэрогриль) с таймером
  на каждый шаг, меню на неделю из рецептов с заказом продуктов в Wolt, список покупок с ценами
  из Wolt и учёт продуктов дома. Заказы из Wolt попадают туда сами через расширение для Chrome.
  У каждого свой аккаунт: план, меню, покупки, «Дома» и заказы свои, рецепты, продукты и цены общие.
- **CLI:** открытые рестораны Wolt не дальше 1 км с хорошим рейтингом.

Стек: FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic, PostgreSQL. Фронтенд — статический SPA
без сборки (`src/static`).

Логотип — надкушенная «e»: исходники `src/static/logo.svg` (слово) и `src/static/favicon.svg`
(иконка). Из них нарисованы PNG-иконки сайта и телефона (`src/static/icons`), `favicon.ico`,
превью ссылок `og.png` и иконки расширения (`extension/icons`).

## Структура

Как в остальных сервисах: `API Route → Service → Repository → Model`.

```
src/
  main.py            точка входа: python src/main.py (в Docker: python3 /app/src/main.py)
  server.py          create_app(): lifespan (миграции, клиенты), роутеры, статика
  config.py          настройки eaty поверх core/config.py, всё из окружения
  api/
    routers.py       карта роутов: /api/v1/...
    dependencies.py  composition root: сессия -> репозитории -> сервисы
    v1/              тонкие роутеры: принять запрос, вызвать сервис
    mcp/             MCP-сервер для Claude: OAuth-вход, страница согласия, инструменты и промпт
  app/
    models/          ORM, модель на файл
    schemas/         Pydantic: *In — вход, *Out — выход
    repositories/    доступ к данным
    service/         бизнес-логика (+ shopping_calculator — чистый расчёт корзины, auth — аккаунты и вход)
    clients/         внешние API: каталог Wolt (async), рестораны Wolt (для CLI)
    utils/           единицы измерения, сопоставление названий, пароли и токены
  core/
    db/              Database (движок + единица работы), Base, миграции из кода
    repository/      BaseRepository и UserScopedRepository (данные одного пользователя)
    service/         BaseService
    fastapi/         зависимости (сессия), middleware
    error/           ошибки приложения и их HTTP-ответы
  migrations/        Alembic
    data/recipe_book.json  начальная книга рецептов, её один раз загружает миграция
  cli/               выбор ресторана рядом
  static/            SPA
extension/           расширение Chrome: заказы с wolt.com -> приложение
```

### Правила, на которых держится архитектура

- **Транзакция одна на запрос, и коммитит её не сервис.** `get_session` открывает
  `Database.transaction()`: если обработчик отработал, транзакция коммитится, если упал —
  откатывается. Репозитории делают только `flush`, сервисы не открывают и не закрывают
  транзакции. Поэтому несколько сервисов в одном запросе (например, «приготовлено»: план
  + списание продуктов) либо проходят вместе, либо не проходят совсем.
- **Коммит до ответа.** Сессия подключена через `Depends(get_session, scope="function")`:
  коммит происходит, когда обработчик вернул результат, но *до* отправки ответа. С обычным
  scope FastAPI закрыл бы зависимость уже после ответа, и клиент получил бы «200 OK» даже
  при упавшем коммите.
- **Зависимости приходят снаружи.** Сервис получает репозитории и другие сервисы в
  конструкторе. Собираются они в одном месте, `api/dependencies.py`, через `Depends`.
  Глобальных синглтонов нет: `Database`, клиент Wolt и фоновая задача создаются в
  `create_app`/lifespan и лежат в `app.state`. В тестах любое звено подменяется через
  `app.dependency_overrides` или передачей своей `Database` в `create_app`.
- **Фоновая работа сама владеет транзакциями.** Обновление цен идёт без запроса, поэтому
  `CatalogRefreshJob` открывает транзакцию на каждый продукт. Сервис ей тоже собирает
  фабрика из `api/dependencies.py`.
- **Сервисы отдают схемы, а не ORM-объекты**, поэтому после коммита ничего не
  догружается лениво.
- **Чужие данные недостижимы по построению.** План, «Дома» и заказы читаются и пишутся
  через `UserScopedRepository`: его собирает `api/dependencies.py` для вошедшего пользователя,
  и общие методы (`get`, `find`, `upsert`, `add`…) сами фильтруют и проставляют `user_id`.
  Поэтому любой обработчик, которому нужен такой репозиторий, без входа отвечает 401, а
  забытый `where` не покажет чужие строки. Свои запросы в репозиториях фильтруют по `self.mine`.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
```

`.env` (в git не попадает):

```ini
ENV=local                                            # перезагрузка при правках, адрес 127.0.0.1
POSTGRES_URI=postgresql+asyncpg://user:password@host:port   # сервер, без имени базы
DB_NAME=eaty
# или целиком: DATABASE_URL=postgresql+asyncpg://user:password@host:port/eaty
```

Ещё есть `PORT` (8080, как ждёт чарт в кластере), `HOST`, `WOLT_CITY` (batumi), `MIGRATE_ON_START` (true),
`ORDERS_MAX_AGE_DAYS` (7), `GROCERY_VENUES_RE` (продуктовые сети), `SESSION_DAYS` (180 — сколько дней
живёт вход), `PUBLIC_URL` (адрес, по которому приложение видят снаружи, см. «Claude по подписке
пользователя»), `MCP_ACCESS_TOKEN_HOURS` (24), `DEBUG`, `ECHO_SQL`. Без `ENV` сервис ведёт себя как в проде: слушает `0.0.0.0`, без перезагрузки.

Базу один раз создать на сервере (psql спросит пароль):

```bash
psql -h <host> -p <port> -U <user> -d postgres -c "create database eaty"
```

Запуск. Миграции накатываются при старте (на пустую базу — вместе с книгой рецептов):

```bash
.venv\Scripts\python src/main.py
```

Открыть http://localhost:8080, документация API — http://localhost:8080/api/v1/docs.

Миграции вручную, из корня: `alembic upgrade head`, новая после правки моделей —
`alembic revision --autogenerate -m "что поменялось"`, сверка моделей со схемой — `alembic check`.

### Аккаунты

Открой приложение и зарегистрируйся: логин и пароль (от 8 символов). У каждого аккаунта свой
план на неделю (новому сразу ставится стандартное меню), «Дома» со списаниями и заказы из Wolt.
Рецепты, продукты и цены из каталога Wolt общие.

- Пароли хранятся как scrypt-хеш с солью, вход — случайный токен в HttpOnly-cookie
  (`SameSite=Lax`, `Secure` по HTTPS). В базе лежит только SHA-256 токена, выход его удаляет.
- **Данные, которые были до появления аккаунтов, забирает первый зарегистрированный.**
  Миграция складывает их в «ничейный» аккаунт, а первая регистрация его занимает. Поэтому после
  обновления зарегистрируйся первым сам, пока приложение не нашёл кто-то другой.
- Регистрация открыта всем, кто может открыть приложение.

### Docker

`Dockerfile` ставит `requirements.txt`, копирует `src/` и `extension/` (для `/extension.zip`) и запускает `src/main.py`. Настройки
передаются переменными окружения (см. выше). В GitLab образ собирает `.gitlab-ci.yml` на
каждый пуш в `main`.

### С телефона

Локально приложение слушает только `127.0.0.1`. На телефон его удобно отдать через Tailscale
(HTTPS, только в твою сеть) — тогда экран не гаснет во время таймеров и приходят уведомления:

```bash
tailscale serve --bg 8080
```

### Расширение для заказов из Wolt

Пошаговая инструкция для пользователей — страница **`/guide`** (https://eaty.lol/guide): расширение и
Claude, без репозитория и терминала. Входить для неё не нужно; она сама видит, что уже сделано (вход на сайте,
стоит ли расширение и к кому оно подключено), и даёт подключить расширение прямо оттуда.
Расширение сайт отдаёт архивом **`/extension.zip`**: его собирает `server.py` из папки `extension`
(в Docker она лежит рядом с `src`), `manifest.json` в корне архива, так что «Извлечь всё» даёт ровно
ту папку, которую ждёт «Загрузить распакованное».

1. `chrome://extensions` → «Режим разработчика» → «Загрузить распакованное» → папка `extension`
   (или распакованный `/extension.zip`).
   После обновления расширения нажми ↻ на его карточке и перезагрузи вкладку wolt.com.
2. Открой приложение: расширение само запомнит его адрес. Если адрес другой, его можно
   вписать вручную в окошке расширения.
3. Вкладка «Дома» → **«Подключить расширение»**: расширение войдёт под тем, кто вошёл на
   сайте, пароль вводить не нужно. Его скрипт на странице приложения сам берёт себе вход
   (`POST /api/v1/auth/extension-token` с cookie страницы), так что токен через страницу не
   проходит, а странице видно только, под каким логином расширение. Можно и войти в окошке
   расширения логином и паролем (`POST /api/v1/auth/token`) — например, если приложение
   открыто по адресу, на котором расширение не работает (Tailscale). Токен у расширения свой:
   выход на сайте его не разлогинивает. Шлётся он заголовком `Authorization: Bearer`, cookie
   приложения расширение для заказов не использует.
4. Вкладка «Дома» → **«Обновить из Wolt»**. Расширение откроет историю заказов на wolt.com
   в фоновой вкладке, по очереди откроет последние заказы, заберёт их и закроет вкладку.
   Ещё оно забирает заказы, которые ты просто открываешь на wolt.com (открытые до входа
   не отправляются — открой их ещё раз).

Берутся только **заказы из магазинов за последние 7 дней**: рестораны пропускаются, а
заказы старше недели в «Дома» не попадают (эта еда уже съедена). Магазин или ресторан
определяется по тому, что есть в заказе: тип заведения от Wolt, адрес на wolt.com (магазины
живут в `/venue/…`, рестораны в `/restaurant/…`), иначе по названию продуктовой сети
(`GROCERY_VENUES_RE`). Незнакомое заведение не берётся. Срок задаёт `ORDERS_MAX_AGE_DAYS`.

Расширение не читает cookie и токены: оно смотрит на данные, которые сайт Wolt сам загружает
для страницы заказа, находит в них заказ и отправляет его в приложение без адресов и
телефонов. Если в данных заказ не нашёлся, он читается со страницы заказа (строки с «×N»).
Разбор сделан по форме данных, корзины и отменённые заказы пропускаются, повторная отправка
ничего не удваивает: продукт заказа попадает в «Дома» один раз. Названия в заказах Wolt Market
грузинские, поэтому у продуктов есть и грузинские шаблоны (в `match_re`/`exclude_re` книги рецептов).

Каждая синхронизация пишется в журнал (`GET /api/v1/wolt-orders/sync-log`). Если заказы не
разобрались, там видно, какие ответы Wolt пришли (адреса запросов и названия полей, без
значений) и как выглядит открытый заказ (без адресов и телефонов). В окошке расширения видно,
что оно смотрело на wolt.com и чем кончилась последняя отправка; «Скопировать отладку»
копирует это вместе со структурой (только ключи и типы, без значений) последнего ответа Wolt,
в котором заказ не распознался. По журналу и отладке и чинится разбор.

Весь разбор идёт в мире страницы (`extract.js` + `hook.js`), а `content.js` только пересылает
найденное в фон и ведёт синхронизацию: Chrome внедряет файл, указанный в двух
`content_scripts`, лишь в один мир.

## Рецепты и продукты

Рецепты, продукты и стандартная неделя живут в базе и общие для всех аккаунтов; по стандартной
неделе новый аккаунт получает свой первый план. Начальную книгу (82 рецепта на 2 порции,
56 продуктов) один раз загружает миграция `recipe_book` из `src/migrations/data/recipe_book.json`;
при старте ничего не перезаписывается. Дальше база пополняется через API (удобно прямо в
http://localhost:8080/api/v1/docs):

- `GET /api/v1/recipes`, `GET /api/v1/recipes/{id}` — список и рецепт с шагами;
- `POST /api/v1/recipes` — добавить, `PUT /api/v1/recipes/{id}` — заменить целиком
  (ответ `GET` можно поправить и отправить обратно), `DELETE /api/v1/recipes/{id}` — удалить
  (запланированный приём пищи останется, но без рецепта);
- `GET /api/v1/products`, `PUT /api/v1/products/{key}` — продукты из Wolt: добавить новый или
  поправить, где и как его искать.

Рецепт выглядит так (тархуна в книге нет, его сначала добавляют как продукт, пример ниже):

```json
{
  "slug": "chakapuli", "title": "Чакапули", "category": "main", "appliance": "stove",
  "batch_note": "На ×2 нужна кастрюля 4 л.",
  "ingredients": [
    {"name": "Говядина", "product_key": "beef", "amount": 500, "unit": "g"},
    {"name": "Тархун", "product_key": "tarragon", "amount": 40, "unit": "g", "note": "1 пучок"},
    {"name": "Соль", "text_amount": "по вкусу"}
  ],
  "steps": [
    {"text": "Мясо нарезать кусками."},
    {"text": "Тушить под крышкой.", "timer_seconds": 3600, "heat": "слабый огонь"}
  ]
}
```

- `category`: `breakfast`, `soup`, `main`, `salad`, `snack`, `dessert`; `appliance`: `stove`,
  `air_fryer`, `none`. Все рецепты на 2 порции, ×2 и ×3 выбираются в плане.
- Ингредиент с `product_key` попадает в список покупок и списывается из «Дома»: количество
  в единице продукта (`g`, `ml`, `pcs`). Масло, соль, специи, мука и сахар пишутся без продукта,
  через `text_amount`.
- Шаг с `timer_seconds` получает кнопку таймера, `heat` — огонь или температура аэрогриля.

Продукт — это то, что покупается в Wolt: `{"name": "Тархун", "base_unit": "g", "venue_slug":
"wolt-market-batumi", "search_q": "тархун", "match_re": "тархун|эстрагон", "exclude_re": "лимонад"}`.
По `search_q` «Обновить цены из Wolt» ищет товары в магазине `venue_slug`, `match_re` и
`exclude_re` решают, какие названия считаются этим продуктом (по ним же разбираются заказы).
Шаблоны разных продуктов не должны пересекаться. Товар берётся, только если его фасовка в
единице продукта: «Лимон, 1 шт» не превратится в 1 г лимонов. У новых продуктов цены
появляются после первого «Обновить цены из Wolt».

## Меню на неделю и заказ в Wolt

Вкладка «Неделя»:

1. **Накидать.** Меню на 7 дней подбирается из рецептов в базе. У рецепта есть `meals` — к
   каким приёмам пищи он подходит (пустой — гарнир или десерт, сам в меню не попадает; если
   при добавлении рецепта `meals` не указан, он берётся по категории: второе блюдо с
   `batch_note` — ужин, остальное второе и супы — обед или ужин, салаты и закуски — обед,
   десерты — никуда). Ужин с `batch_note` готовится ×2, и его вторая половина
   становится обедом на завтра, после остального ужина обед — отдельный рецепт. Блюда
   чередуются: одно и то же не попадает дважды в день и на тот же приём пищи два дня подряд.
   Уже приготовленное не трогается. Меню — это обычный план (`/plan`), его видно на «Сегодня».
2. **Черновик.** ↻ у блюда меняет его на другое. Новый ужин заодно решает, что будет на
   обед завтра. «Перемешать всё» подбирает меню заново.
3. **Утвердить → «Ждёт заказа».** Появляются корзины по магазинам: что положить и сколько,
   со ссылками на товары. Это нужно от сегодня до конца меню минус то, что уже есть дома.
   «Скопировать задание для Claude» копирует тот же список текстом с правилами: замены, не
   платить без твоего «да». Его можно отдать Claude в браузере (или сказать Claude Code
   «закажи меню в Wolt», см. `.claude/skills/wolt-order`). Если eaty подключён к Claude как
   коннектор, хватит промпта «Собрать корзину в Wolt» (см. ниже). Можно и самому заказать по ссылкам.
4. **«Заказано».** Расширение забирает заказ, когда ты открываешь его на wolt.com или
   жмёшь «Обновить из Wolt». Заказы, оформленные после утверждения, привязываются к меню.
   Когда докупать больше нечего, меню само становится «Заказано». Если заказ пришёл не весь
   (например, только мясо), в меню остаётся то, что ещё нужно. «Уже всё заказано» отмечает
   вручную.

Шаг назад есть всегда: «Заказано» → «Ждёт заказа» → черновик. Утверждённое меню на эти
дни не перезаписывается новым, черновик перезаписывается. Меню у каждого аккаунта свои.

API: `GET /api/v1/menus?status=awaiting_order`, `POST /api/v1/menus {start}`,
`POST /api/v1/menus/{id}/{day}/{meal}/swap`, `PUT /api/v1/menus/{id}/status {status}`,
`GET /api/v1/menus/{id}/order` (корзины и `task` — текст задания).

## Claude по подписке пользователя (MCP)

eaty — MCP-сервер по адресу `{PUBLIC_URL}/mcp`. Каждый пользователь подключает его к **своему**
Claude, и корзину собирает его Claude на его подписке: eaty не видит ни ключей, ни входа в Claude
(Anthropic не разрешает приложениям ходить в Claude через чужие подписки, а так всё честно —
пользователь сам зовёт своего Claude, eaty для него просто коннектор).

Подключить (адрес с кнопкой «Скопировать» есть на вкладке «Дома», пошагово — на `/guide`):

- **claude.ai / приложение Claude:** Customize → Connectors → «+» → Add custom connector → адрес
  `https://<сайт>/mcp`. Claude откроет страницу eaty «просит доступ»: войти и нажать «Разрешить».
  На бесплатном плане Claude свой коннектор можно добавить только один.
- **Claude Code:** `claude mcp add --transport http eaty https://<сайт>/mcp`, потом `/mcp` → войти.

Что внутри:

- промпт **`wolt_order` «Собрать корзину в Wolt»** (в Claude Code — `/mcp__eaty__wolt_order`): задание
  для меню, которое ждёт заказа (то же, что «Скопировать задание для Claude»), плюс как класть в
  корзину Wolt, не теряя товары, и правило «не платить без моего „да“»;
- инструменты (только чтение): **`wolt_order`** — корзины по магазинам со ссылками и количеством,
  **`menu_status`** — статус меню и заказы, которые вернуло расширение.

Корзину Claude собирает в браузере, где открыт Wolt пользователя, поэтому нужен Claude, который
управляет Chrome (Claude в Chrome, Claude Code с `/chrome`). Без браузера он отдаст список ссылками.

Вход — OAuth 2.1 из MCP SDK: Claude сам регистрируется (`/register`), `/authorize` ведёт на
страницу согласия `/oauth/consent` (там же можно войти, если на сайте не вошли), `/token` выдаёт
токены (PKCE обязателен; access живёт `MCP_ACCESS_TOKEN_HOURS`, refresh — `SESSION_DAYS` и
меняется при каждом обновлении), `/revoke` отзывает. Коды и токены лежат в базе только хэшами.
Метаданные: `/.well-known/oauth-authorization-server` и `/.well-known/oauth-protected-resource/mcp`.

**В проде обязательно задать `PUBLIC_URL`** (например, `https://eaty.lol`): это издатель
токенов и адрес ресурса, по умолчанию он `http://localhost:{PORT}`, и Claude снаружи с ним не
подключится. Все пути выше должны проходить через прокси до приложения.

## Тесты

```bash
pytest                              # без базы тесты с БД пропускаются
node --test tests/extract.test.mjs  # разбор заказов в расширении
node --test tests/extract_page.test.mjs  # чтение заказа со страницы, в Chromium через Playwright
```

Тест страницы пропускается без Playwright; с глобальной установкой нужен `NODE_PATH`
(`set NODE_PATH=%APPDATA%
pm
ode_modules`). Страница в `tests/fixtures` повторяет настоящую
по скриншоту.

Тесты с базой (миграции, книга рецептов, API, аккаунты, откат транзакции) идут при заданном `TEST_DATABASE_URL`.
База **стирается**, поэтому нужен локальный сервер или база с `test` в имени. Без установки
Postgres его можно поднять в памяти через PGlite:

```bash
npx -p @electric-sql/pglite-socket -p @electric-sql/pglite pglite-server --db=memory:// --port=5499 --max-connections=8
set TEST_DATABASE_URL=postgresql+psycopg://postgres:postgres@127.0.0.1:5499/postgres
pytest
```

С PGlite нужен драйвер psycopg (asyncpg с ним не работает), с настоящим сервером подходят оба.
